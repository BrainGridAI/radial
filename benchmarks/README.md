# Radial issue-tracker benchmark

An open benchmark of issue trackers as coding agents use them. It compares Radial, Linear, Jira Cloud and a no-tracker baseline (`TODO.md` in git) on nine agent tasks: create, pick up, update with proof, close, find a past decision, share a prototype, hand off, and resume. Every number here points to a raw output file in this folder and a command that produced it.

This is an interim release, dated 2026-11-02. It has an offline phase (baseline, Radial CLI and MCP surfaces, vendor docs) and a first live phase (Linear's official MCP and API, Radial's hosted MCP tool list). Jira live runs and the human-side runs are not done yet. See [Limitations](#limitations).

## Evidence labels

Every number carries exactly one label.

- **MEASURED**: produced by a command in this folder. The raw output is under `runs/2026-11-02/`.
- **DOCUMENTED**: quoted from a vendor page (URL in `runs/2026-11-02/sources/`), or for Radial, from the Radial app source at commit 9126321 (private repo; tool lists reproduced from the public hosted MCP).
- **SIMULATED**: produced by a scripted agent. It measures the tool floor (git, shell, HTTP), not an LLM.
- **ESTIMATE**: an assumption with its reasoning written next to it. Estimates never feed a "winner" claim.

## Results

All rows dated 2026-11-02. The id column is the key in `evidence.json`.

### Live phase

| Id | Result | Label | n |
|---|---|---|---|
| L-LIVE-MCP-TOOLS | Linear official MCP (`mcp.linear.app/mcp`, server 1.0.2) exposes **60 tools**. The `tools/list` response is **101,447 bytes** | MEASURED | 1 |
| R-LIVE-MCP-TOOLS | Radial hosted MCP (`mcp.radial.build/mcp`) exposes **45 tools**. The `tools/list` response is **21,020 bytes** | MEASURED | 1 |
| L-LIVE-T1T4 | Linear T1 to T4 through MCP (create, list next, claim and start, proof comment, done, done-note) takes **6 MCP calls**, median **3,187 ms** wall (min 2,608, max 3,293), about 9.1 KB read back per flow | MEASURED (scripted calls, no LLM time) | 5 |
| L-LIVE-RACE | Linear claim race, 10 rounds x 20 workers: **10 of 10 rounds** had more than one worker told "claimed". **183 silent overwrites** in total: 193 workers got `success`, 10 issues ended with one owner each | MEASURED | 10 rounds |
| R-CLAIM-ATOMIC | Radial atomic claim (`POST /v1/issues/{id}/claim`, MCP tool `claim_issue`) is live on production. Its live multi-identity race was **not run** | DOCUMENTED | n/a |

How to read the race. The Linear run used one API key from 20 threads. Linear has no conditional update, so each worker reads the issue, and if it still says Todo, calls `issueUpdate`. Every update returns `success`, and the last write wins. Separate identities do not add a precondition, so we expect the same outcome; that run was not done. For Radial, the claim endpoint rejects every claimant after the first. The evidence for that today is a 12-way concurrent unit test in the Radial app repo (private). A live race needs several agent keys and is the next run.

How to read the tool-list bytes. The `tools/list` payload is what an MCP client loads into the agent's context before the first call. Linear's 60 tools average about 1,690 bytes each; Radial's 45 tools average about 470 bytes each. Fewer bytes is not more capability: see `coverage-matrix.md` for what each surface can do.

## How to reproduce

```sh
cd benchmarks
./reproduce.sh plan        # every step, its label, what it needs, where it writes
./reproduce.sh offline     # baseline + derived files; no network, no credentials
./reproduce.sh tokens      # paid: 3 claude -p trials, about $0.07 each
LINEAR_API_KEY=... ./reproduce.sh linear   # live Linear: tools/list, T1-T4 n=5, claim race
scripts/scan_secrets.sh    # must print PASS before any commit
```

Requirements: Python 3.11+, git, bash, jq. `tokens` needs Claude Code. `offline` steps S01 to S04 also read the Radial app source and need `RADIAL_REPO` pointing at a clone of the private app repo; without it they are skipped, and the hosted MCP tool list in `runs/2026-11-02/radial-live/` stands in.

`./reproduce.sh linear` writes 15 issues (5 task issues, 10 race issues) to the Linear workspace behind the key. Use a scratch workspace. The key is read from `LINEAR_API_KEY` only and is never written to disk or printed. The viewer id is used for the assignee field and never written to the outputs.

The Radial hosted `tools/list` was captured with the same JSON-RPC client as `scripts/linear_live.py` (initialize, `notifications/initialized`, `tools/list`) against `https://mcp.radial.build/mcp` with an `rk_` key. Only the tool names, count, bytes and latency are stored.

## Limitations

- **No live Radial task run yet.** Linear has live T1 to T4 timings; Radial does not. The Radial CLI rows are offline (startup, help bytes, static request counts). Do not compare L-LIVE-T1T4 to any Radial latency here.
- **Radial's live claim race was not run.** Atomicity rests on a unit test in a private repo. Until the live multi-identity race lands, treat R-CLAIM-ATOMIC as DOCUMENTED, not MEASURED.
- **The Linear race used one identity.** See "How to read the race" above.
- **Scripted calls, not agents.** L-LIVE-T1T4 and the baseline task timings are scripted. They include network and server time but no LLM reasoning. The only LLM numbers are the three token trials, and n=3 is below our n >= 5 bar.
- **Coverage cells for Linear still cite docs.** The live tool list resolves the tool count, but the 8 `unknown` Linear MCP cells in `coverage-matrix.md` have not been re-scored from it.
- **Jira is docs-only.** No live Jira run. Jira tool counts come from docs and an observed client list.
- **Rows were chosen for coding-agent workflows.** Three capability rows (prototype preview, session logs, done-proof) describe features only Radial ships. The table shows scores with and without them.
- **Radial source snapshots are not published.** The app repo is private. This folder ships derived lists (tool names, REST routes, CLI help, request counts) and the live hosted tool list instead.
- **Redactions.** Claude Code session ids in `runs/2026-11-02/tokens/*.json` are replaced with `<redacted>`. One example agent identity in `radial-static/cli-task-plan.json` is replaced with `<agent-b-identity>`. The token-trial `.meta.json` files had an empty `wall_s` from an earlier harness version; it is `null` here. No other output was edited.
- **Vendor pages change.** DOCUMENTED rows are as of November 2026.

Results where Radial loses or ties stay in every table.
